# Known divergences: Rust engine (rt/0.111.0) vs the real game 0.111.0

이 브랜치(`rt/0.111.0` = 원작자 f79727f + 0.111.0 수정)에서 알려진, 아직 고치지 않은 실제 게임과의 차이 메모. 2026-10-21 작성. 이 브랜치의 수정은 모두 `>= V0_111_0` 게이트이고 0.107.1 동작은 원작자와 같다.

"실제 게임"의 기준은 C# 디컴파일 0.111.0과 C# 헤드리스 오라클(실제 DLL + 덤프 명령). 학습용 sts2-cli 헤드리스도 정답이 아니다(3절).

## 재현 방법
- 같은 시드·같은 행동열로 이 엔진과 오라클을 나란히 진행하며 걸음마다 상태와 `rng_dump` 카운터를 비교한다(오라클 lockstep). 첫 갈라짐 지점이 증상이다.
- 시드는 대문자·숫자·`_`만(I/O 없음) 쓴다 — 엔진은 기본으로 대문자화 + I→1·O→0 정규화 뒤 해시한다.
- 아래 시드 이름: `P0A<n>`은 하네스 고정 시드, `LSA_<n>`은 무작위 행동(금 3000) 비교 시드.

## 2. 엔진 사용상 주의
- **게임 버전 기본값이 0.107.1** — `RunManager`·`CombatState`·`build_scenario_state`·`roll_acts`에 `game_version="v0.111.0"`을 명시해야 한다(또는 `STS2_GAME_VERSION`). 빠뜨리면 조용히 0.107.1로 돈다.
- **시드 정규화**: 기본은 대문자화 + I→1·O→0 뒤 해시(실제 게임과 같음). 원문 해시가 필요하면 `RunManager(..., raw_seed_hash=True)`(전 계보 검증됨).
- **엔진은 행동 입력을 검증하지 않는다** — 잘못된 `card_index`도 `advanced`를 돌려준다. 호출 쪽에서 `legal_actions()`로 먼저 거른다.
- **보스 유물 단계 = 다음 막 고대 이벤트의 3택**(유물·순서가 C# 고대 제시와 같음). 실제 게임처럼 보이려면 고대 이벤트 화면으로 표현한다.
- **시나리오(전투 단독) 생성**: 이벤트 전용 조우 8종은 없고, DOWSING_ROD·NEOWS_SACRIFICE는 전투 유물 레지스트리에 없어 시나리오 생성이 거부한다.
- 와이어에 없는 것: 유물 `vars`(카운터), 파워·유물 설명, 카드 `after_upgrade`, 전투 중 카드 선택의 문구 키(prompt). 최대 에너지는 `max_energy_effective`(이 브랜치 추가)로 본다.

## 3. sts2-cli 헤드리스 쪽 차이 — 이 엔진(실제 게임)이 맞는 것
- 오래 가는 사탕: 헤드리스가 `BeforeCombatRewardOffered`를 부르지 않아 발동 안 함.
- SpecialCardReward(랜턴 열쇠, 소매치기 반환 카드)를 헤드리스가 버림(엔진은 둘 다 선택형 보상으로 내놓음).
- 가짜 상인(FakeMerchant) 이벤트를 헤드리스가 건너뛰고 바로 지도를 냄(엔진은 이벤트 화면을 냄).
- 기도 바퀴·하얀 별의 추가 카드 보상 화면을 헤드리스가 보여 주지 않음(난수는 읽음).
- 보물방에서 유물을 금보다 먼저 받음(실제 게임은 금 먼저).
- 상점 카드 제거를 한 방문에 여러 번 허용(C# `MerchantCardRemovalEntry`는 1회).
- 노멀리티(한 턴 3장)가 걸려도 4번째 카드 허용.
- 크리스털 구체 이벤트를 건너뜀.
- 전투 보상: 배틀웜 더미 이벤트의 중첩 전투가 골드·카드 보상을 줌(실제 게임은 `ShouldGiveRewards == false`라 이벤트 고유 보상만 줌).
- 수정구(CrystalSphere)와 가짜 상인(FakeMerchant) 이벤트를 화면 없이 건너뜀(상태·난수 소비가 실제 게임과 다름; 가짜 상인은 상점 난수를 6번 읽음).
- 카드 선택 화면의 `max_select`를 후보 수로 자르지 않고 카드의 설정값 그대로 알림(러스트는 후보 수로 자름).
- 오래 가는 사탕의 추가 카드 보상 난수를 읽지 않음(위 항목과 같은 뿌리).
- 날개 달린 신발이 남은 동안 지도 선택지를 다음 줄 전체로 내는 것은 오라클(OracleWingedBootsChoices)이 맞고, 어댑터가 자식 노드만 남기던 필터는 구형 골든 기준이다(엔진은 전체 줄을 낸다).
- 죽인 타격 뒤 카드 생성(앵거의 복사본 등): 엔진은 전투가 끝나는 중이면 생성하지 않는다(`AddGeneratedCardsToCombat`은 진행 중일 때만). 뱀눈 아래에서 이 생성이 비용 난수를 한 번 더 읽던 차이가 사라졌다.

## 4. 이 브랜치에서 고친 것(요약)
시드 경로(`old` 접두 판정 순서·`old`+roll 막 선택 해시·원문 해시 옵션)와 측정용 `rng_dump`·`player_seed`; 전투방 `Hook.ModifyRewards` 배선(기도 바퀴·하얀 별·용암석·Wongo 추가 보상 누락 → 보상 난수 연쇄 어긋남), 고대 진입 회복 시점, 퀘스트 카드의 인챈트·변환 제외, 할인가 구매 가능 판정, 바다 유리·유리 눈·오로바스 풀·파엘의 이빨 획득 효과, 전리품 지도의 2막 지도 교체·퀘스트 완료; 전투: 고대의 이빨 덱 순서, Finesse+ 방어도, 연속 강화 선택, Shrink 유지, 위협적인 투구 자동 사용 카드, 불타는 막대기, Goopy 소멸, 파엘의 살 최대 에너지, 최대 체력 감소 피해, 마지막 일격 뒤 드로, 소매치기의 강화 카드 도난.

2026-10-21 추가: 전투 단위 — 죽인 공격은 AfterDamageReceived를 건너뜀, 노멀리티의 자동 사용 금지, 상상 부여 카드(Imbued)는 첫 턴 뽑을 더미 맨 아래에서 자동 사용, 속삭이는 귀걸이의 첫 턴 자동 사용, 눈부신 스카프의 5번째 카드 비용 0, 철학자의 돌의 중간 소환 힘, 일반 계몽(Enlightenment)의 한 턴 비용, 여왕의 AfterDeath 즉시 이동 교체; 비전투 — 이벤트 시작 난수(가짜 상인 6회, 전투 배치형 이벤트의 니치 HP 롤), 이벤트가 덱에 직접 넣는 카드의 럭키 피시·알 유물 훅, 휴식처 선택지 순서(유물 획득 순), 공생체 부패 인챈트는 공격만, 영양 수프의 인챈트 효과(비용 0), 상점 카드의 알 유물 업그레이드(와이어 `upgraded` 키).

2026-10-21 V1 수리 2차: 선택 상한을 후보 수로 자르지 않음, 시험체의 화상은 버린 더미로, 재판(Trial) 3쪽 흐름과 판결 보상 선발행, 저글링 짓밟기 복사본 비용 유지, 영혼의 힘 인챈트는 소멸 제거, 강화 곱셈은 기본 피해에만(힘 가산 앞), 자동 사용 카드도 인챈트 OnPlay/AfterCardPlayed, 눈부신 스카프는 자동 사용 제외, 턴 시작 피해로 끝난 전투는 AfterSideTurnStart 생략(행복한 꽃·석궁), 아이템 금지 규칙(3막 보물방 이후 17종, 고대 방 수 반영), 전쟁 망치·돌의 검 승리 훅 연결, 모피 코트 표시·1HP, 파엘의 눈물 래치 초기화, 죽인 뒤 카드 생성 금지.
